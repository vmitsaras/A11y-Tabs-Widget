Dynamic page fragments

Initialize tabs when content arrives

Install one explicit auto-init controller for the page, then request a scoped scan whenever routed or server-rendered content is inserted.

Scenario

An account page renders one tabs component with the document and later inserts another component from a routed fragment. The add-on handles the initial document-ready scan and a deliberate initialization event without observing every DOM mutation.

Try it

  1. Use the existing account tabs with Arrow keys, Enter, and Space.
  2. Select Insert routed tabs to add semantic markup and dispatch a scoped request.
  3. Request initialization again and confirm that the existing instance is reused.
  4. Destroy and remove the routed tabs, then insert them again.

Implementation notes

  • Importing the add-on does not initialize anything; installTabsAutoInit() is the explicit opt-in.
  • The request event is a11y-tabs:request-init, which is distinct from the post-init a11y-tabs:init lifecycle event.
  • The event target becomes the scan scope, so unrelated page regions are not queried.
  • Repeated requests reuse the core tabs instance and do not duplicate listeners or markup.
  • controller.destroy() removes auto-init listeners but does not destroy application-owned tabs.

Initialize newly inserted content before moving focus into it. A late initialization can hide inactive panels, so it should not run while a user is already interacting inside that fragment.

How it works

Install once

import {
  A11Y_TABS_INIT_REQUEST,
  installTabsAutoInit
} from "../../dist/addons/a11y-tabs-autoinit.js";

const autoInit = installTabsAutoInit();

Request a scoped initialization

container.dispatchEvent(
  new Event(A11Y_TABS_INIT_REQUEST, { bubbles: true })
);

// Removes only the controller's listeners.
autoInit.destroy();
