Responsive add-on demo

FAQ tabs that adapt when labels stop fitting

Compare common account questions in desktop tabs or required-open disclosure controls when the tablist wraps or overflows. The same selected answer and focus context are preserved when the presentation changes.

Scenario

A support page needs compact desktop tabs and readable narrow-screen disclosures without maintaining two copies of the same answers.

Try it

  • At wider widths, use Arrow keys, Home, and End to move between tabs.
  • Press Enter or Space to activate a focused tab in manual mode.
  • Choose Constrained to make the labels stop fitting, then use Tab to reach each disclosure.
  • Resize while a control is focused and confirm focus moves to its equivalent control without changing the answer.

Accessibility behavior

  • All source answers remain readable if JavaScript is unavailable.
  • Generated controls are real buttons with aria-expanded and aria-controls.
  • The required-open control remains focusable and exposes aria-disabled="true".
  • State is exposed through the controls, so the demo does not add a duplicate live announcement.
  • No animation is required, and visible focus is preserved.

Developer setup

Initialize the core tabs first, then pass the instance to the responsive adapter. Repeating the add-on constructor for the same root reuses the existing instance. 

import { createTabs } from "a11y-tabs-widget";
import { A11yTabsAccordion } from "a11y-tabs-widget/addons/a11y-tabs-accordion";

const root = document.querySelector("[data-a11y-tabs]");

if (root instanceof HTMLElement) {
  const tabs = createTabs(root);
  const accordion = new A11yTabsAccordion(tabs, {
    // This demo responds only to the tablist's actual layout pressure.
    mediaQuery: false
  });

  // Remove only the responsive adapter when needed.
  // accordion.destroy();
}

By default, wrapping/overflow and (max-width: 40rem) can each trigger the adapter. This demo uses mediaQuery: false to demonstrate container-only behavior. The adapter preserves the tabs single-selection model; it is not a multi-open standalone accordion.

How it works

The source stays a normal tabs component. After the core initializes, the accordion adapter watches available space and creates synchronized disclosure buttons when the tablist no longer fits.

HTML

<div class="a11y-tabs" data-a11y-tabs>
  <div data-a11y-tabs-list aria-label="Help topics">
    <button type="button" data-a11y-tabs-tab data-a11y-tabs-panel-id="account">
      Account security
    </button>
    <button type="button" data-a11y-tabs-tab data-a11y-tabs-panel-id="access">
      Workspace access
    </button>
  </div>
  <section id="account" data-a11y-tabs-panel>...</section>
  <section id="access" data-a11y-tabs-panel hidden>...</section>
</div>

JavaScript

import { createTabs } from "../../dist/index.js";
import { A11yTabsAccordion } from "../../dist/addons/a11y-tabs-accordion.js";

const root = document.querySelector("[data-a11y-tabs]");

if (root instanceof HTMLElement) {
  const tabs = createTabs(root);
  new A11yTabsAccordion(tabs, { mediaQuery: false });
}
