Build and initialize

Install this repository's development dependencies and build the browser ESM files before opening the local examples.

Repository setup

npm install
npm run build

Basic initialization

import { createTabs } from './assets/index.js';

const root = document.querySelector("[data-a11y-tabs]");

if (root instanceof HTMLElement) {
  createTabs(root, { activation: "manual" });
}

Package-name note: The registry package name is a11y-tabs-widget. Use this name when copying a package-install command.

Options, methods, and events

Pass options to createTabs() or provide matching data-a11y-tabs-* values on the root.

OptionTypeDefaultPurpose
activation"manual" | "automatic""manual"Controls whether focus or explicit activation selects a tab.
orientation"horizontal" | "vertical""horizontal"Selects the arrow-key model and vertical ARIA orientation.
dir"auto" | "ltr" | "rtl""auto"Controls horizontal arrow-key direction.
useHashboolean | stringfalseReads and updates panel selection through the URL hash.
scrollSelectedIntoViewboolean | stringtrueKeeps focused and selected tabs visible in an overflowing tablist.
initialIndexnumber | stringnullSelects an initial enabled tab when hash activation does not apply.

Instance methods

  • activate(indexOrId)
  • activateByPanelId(panelId)
  • next() and previous()
  • getActiveTab() and getActivePanel()
  • destroy()

Bubbling events

  • a11y-tabs:init
  • a11y-tabs:before-change (cancellable)
  • a11y-tabs:change
  • a11y-tabs:destroy

Accessibility and keyboard behavior

The runtime applies the ARIA tabs pattern after initialization, maintains roving focus and tab-panel relationships, skips disabled controls, and restores the original DOM state on destroy().

KeyBehavior
ArrowLeft / ArrowRightMoves focus in horizontal tablists and follows right-to-left direction.
ArrowUp / ArrowDownMoves focus in vertical tablists.
Home / EndMoves to the first or last enabled tab.
Enter / SpaceActivates the focused tab in manual mode.

The plugin does not add a live announcement for ordinary tab changes because the focused tab, selected state, and tabpanel relationship expose the change. Test the final integration with your target browsers and assistive technologies.

Styling hooks and limitations

Public styling hooks

  • .a11y-tabs, .a11y-tabs__list, .a11y-tabs__tab, and .a11y-tabs__panel
  • .is-initialized, .is-active, and .is-disabled
  • Custom properties prefixed with --a11y-tabs-*
  • Bundled focus, forced-colors, and reduced-motion rules

Integration limits

  • Provide one tablist per root and one meaningful panel per tab.
  • The runtime does not create author content or a multi-select disclosure pattern.
  • Keep panel content readable before JavaScript applies hidden state.
  • Test hash behavior with any client-side router before enabling it.

How the basic example works

The HTML provides real buttons, stable panel ids, and readable fallback content. JavaScript enhances that structure with the tabs interaction model.

HTML

<div class="a11y-tabs" data-a11y-tabs>
  <div data-a11y-tabs-list aria-label="Product information">
    <button type="button" data-a11y-tabs-tab
      data-a11y-tabs-panel-id="snippet-details">Details</button>
    <button type="button" data-a11y-tabs-tab
      data-a11y-tabs-panel-id="snippet-shipping">Shipping</button>
  </div>
  <section id="snippet-details" data-a11y-tabs-panel>...</section>
  <section id="snippet-shipping" data-a11y-tabs-panel hidden>...</section>
</div>

JavaScript

import { createTabs } from "./dist/index.js";

const root = document.querySelector("[data-a11y-tabs]");

if (root instanceof HTMLElement) {
  createTabs(root, { activation: "manual" });
}

With manual activation, Arrow keys move focus; Enter or Space selects the focused tab. The runtime also manages role, aria-selected, aria-controls, roving tabindex, and inactive panel visibility.
